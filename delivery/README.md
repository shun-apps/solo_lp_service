# 納品版の原型（営業デモとは別）

このディレクトリは顧客向け納品物の**本体の開発**です。営業シミュレーターは後で追加します。現行の営業デモはこの原型とはまだ同一ではありません。

## 今回の実装

- 別ビルド（npm run build:delivery）で同じ管理画面HTMLとCSSを使用し、デモ固有の画面・架空の個人情報を排除
- 管理画面へのBasic認証と顧客ごとのD1データ保存の基礎
- LP3本の公開URL管理、LP別の申込・相談件数、イベント作成・編集・受付停止・再開、受付一覧とキャンセル／対応済み
- 公開フォーム：/form/lp-event、/form/lp-content、/form/lp-craft
- 公開フォームは管理画面と同じDBを参照。申込時に最新の残席と受付可否を再検証
- 顧客単位の状態の整合テストと管理者APIのアクセス制御テスト

同じLPを再納品せず開催日・定員を変えられます。ただし、LPの画像や本文に直接埋め込まれた固定の日付は変わりません。開催情報は公開フォームを正本とします。

## 未完成・納品禁止

**現時点では本番納品・顧客情報の投入をしないでください。**

- 自動サンクスメール・リマインドメールの実送信と送信ドメイン認証
- 画像のショップアイコン登録（暫定はショップ名の頭文字）
- スパム対策／レート制限、認証運用、個人情報の取り扱い、バックアップ、監視
- 本物のCloudflare D1での同時申込負荷試験、LP3本の実URL連携確認

使えない機能は納品版の画面で「準備中」と明示し、営業デモの架空機能を納品機能とは呼びません。

## 開発

- Node.js 22以上
- npm run check:delivery
- npm run build:delivery

顧客別Workerの設定例は delivery/wrangler.delivery.example.jsonc、D1初期化は delivery/schema.sql です。デモと納品先ではWorker・DBを共有しません。
ADMIN_USERNAME と ADMIN_PASSWORD はCloudflare secretsで設定し、ソース・リポジトリに記録しません。

## 開発方針

1. 納品可能な管理画面と公開フォームを本体として完成させる
2. 実環境で動作と運用・個人情報保護を検証する
3. 同じ画面・業務ロジックに架空データを供給するシミュレーションレイヤーを追加する

営業用シミュレーターを本体に混ぜたり、実際に納品できない業務機能を体験だけで追加したりしない。
