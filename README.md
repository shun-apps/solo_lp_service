# ハンドメイド作家向けLP＋アトリエ管理：動画から始める操作体験版

整体院版で評価された管理画面の操作感を引き継ぎ、ハンドメイド作家さんの作品販売・オーダー受付・ワークショップ申込に絞った**独立デモ**です。

## リポジトリ・公開環境

- GitHub: `shun-apps/solo_lp_service`（個人事業主専用）
- Cloudflare Workers: **`solo-lp-demo`**（整体院版 `seitai-lp-demo` と別Worker）
- 本番ブランチ: `main`（テスト通過後にマージ）
- GitHub連携のCloudflare公開URLは、初回Worker作成後に発行されます
- 整体院版・瞬LP V2のソース、Worker、DBやGoogle設定には一切触れません
- 公開デモは静的データで動く操作体験版。実イベント申込や実問い合わせの受付ではありません

## デモの導線（説明と体験を分離）

- 入口：実際の画面操作を録画した無音の短い動画で「申込→管理画面反映→対応」の全体像を見せる
- **操作を体験する**：説明段落を極力消した管理画面へ。後半に紹介コピーを混ぜない
- フォーム：瞬LP V2の公開フォームと同じ基本的な1問1画面・進捗・確認画面での「修正する」・送信完了の順序
- **実フォームではない**：実名・実メールの入力を防ぐため、名前とメールアドレスは架空データを読み取り専用表示
- ワークショップの参加人数は疑似残席に反映し、全操作はブラウザ内のメモリだけで完結
- 約20秒の無音デモ動画を`public/media/demo-overview.mp4`に同梱。`scripts/record-demo.mjs`で、架空データだけを使った実画面を録画して生成したもの

## 提供画面

- ダッシュボード（LP 3本・ワークショップ件数・参加申込数・未対応のオーダー相談）
- LP管理（作品販売／オーダー受付／ワークショップ募集の**仮見本**3本）
- ワークショップ管理（日付・時間・定員・受付ON/OFF、追加・編集）
- 申込・お問い合わせ（ワークショップ参加申込とオーダー相談の別タブ、キャンセル・対応済み操作）
- フォームの設定（ワークショップ申込／オーダー相談の既定フォーム切り替え）
- 自動返信メール（**送信しない**プレビュー）
- 作家プロフィール（架空アトリエ名の変更）

## 2種類の疑似体験

### ワークショップ申込
お名前（架空・自動入力）→メール（架空・自動入力）→日時と参加人数→内容確認（修正可能）→デモ送信→管理画面で反映を確認。

申込数が増え、残席が減る。定員に達したイベント・受付停止中のイベントでは申し込めない。

### オーダー相談
フォームの種類を選ぶ → LPの流入元を選ぶ → 作品についての相談内容を選ぶ → 架空のお客様情報を確認 →「送信を確定する（デモ）」→ 管理画面の問い合わせ一覧に新着が増える。対応済み状態を変更できる。

## ビジュアル設計（既存レイアウト維持）

- ベースの `styles.css` と管理画面の構造は維持
- `theme-handmade.css` の上書きで、**くすみローズ／グレージュ／ブルーグリーン**に統一。アイボリーとラベンダーは使用しない
- 主要操作ボタンは濃いローズ（`#964A64`）、背景はニュートラルなグレージュ（`#F2F0EF`）、申込・操作状態はブルーグリーン（`#397C7D`）
- 左サイドバー先頭には架空のショップ名とアイコンを表示し、重複する「瞬apps／アトリエ管理」のロゴ帯は削除
- **文字サイズ（PC基準）**：ショップ名16px、ナビ15px、ページ見出し26px、カード見出し18px、説明文14px、注釈13px、ボタン14px。KPI数字34pxは維持
- スマホではナビ14px・ページ見出し25px。狭い画面のCTAは折り返し、表の横スクロールを維持して文字を潰さない
- LP見本は「作品販売LP」「オーダー受付LP」「ワークショップ募集LP」。1つの架空ブランド「糸と花のアトリエ」を想定
- **本物の完成LPではなく、構成を示す仮カード**。まだ実LPへのリンクは付けていない

## セキュリティとデータ

- 顧客の実名、実メール、電話番号を入力させない
- 予約・問い合わせは**そのブラウザのメモリにのみ存在**。他の閲覧者と共有しない
- \`localStorage\`、\`sessionStorage\`、DB、Google、実際のメール、外部APIへの送信なし
- 再読込で初期状態に戻る
- Cloudflare WorkerはGET/HEAD以外405、\`/api/*\` は404、CSPで送信禁止
- \`noindex\` を設定。正式営業サイト完成後に別途見直す

## 販売条件（ユーザー方針を記録、実装は別）

- 対象：SNSで作品を販売しているハンドメイド作家（特に作品販売の実績がある方）
- 完全後払い：完成後に内容を確認してから支払う
- **完成案内から24時間以内の入金で40,000円**（税込・税別未確定）
- 通常価格、24時間後の取扱い、キャンセル期限、正式納品のタイミングは販売開始前に明文化する
- 未払いのままZIP・編集可能なソースを正式譲渡すると未回収のリスクがあるため、**完成プレビューと正式納品は分離**することを推奨
- 商品・納品範囲、修正回数、サーバー費用、イベント通知やスプレッドシート連携の有無は販売前に決める
- このデモ管理画面に販売コピーや価格表を押し込まず、営業導線は別に用意する

## Cloudflare Workersの初回公開

- Worker名：\`solo-lp-demo\`
- Repository：\`shun-apps/solo_lp_service\`
- Production branch：\`main\`
- Build：\`npm run build\`
- Deploy：\`npx wrangler deploy\`
- Root：リポジトリルート
- 既存の整体院版Worker・瞬LP V2には変更を加えない

**GitHubは作成済み。Cloudflare上の初回公開も実施済みです。** mainマージ後はCloudflare側で更新が反映されたことを確認してください。

## GitHubリポジトリの公開範囲

初回確認時のVisibilityは **Public** でした。ユーザーの当初希望はPrivateのため、GitHubのSettings → General → Danger Zone → Change repository visibilityでPrivateへの変更を推奨します。公開済みコードにAPIキーや個人情報は含めません。

## テスト

`npm run check`（単体・構文）、`npm run build`（Workers Static Assets生成）、GitHub ActionsのPC・スマホブラウザ操作テストを実行します。
